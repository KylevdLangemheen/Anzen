# Contributing

Thanks for your interest in contributing! All kinds of contributions are welcome: bug reports, feature requests, documentation improvements, and code changes big or small. If it's your first time contributing to Anzen, _smaller changes are better_!

## Opening an Issue

Before opening a pull request, please open an issue first. This gives us a chance to discuss the change before you invest time writing code, and helps avoid duplicate effort or misaligned direction.

When opening an issue:
- **Bug reports** — describe what happened, what you expected, and steps to reproduce. Include your Python version and any relevant logs
- **Feature requests** — describe the problem you're trying to solve, not just the solution. This helps with discussion
- **Questions** — feel free to open an issue for questions

## Making Changes
Ensure that branch names and PR titles/descriptions are descriptive in what they address!

1. **Fork** the repository and create your branch from `main`
2. Install `pre-commit` in your local fork
3. Make your changes, keeping commits focused and descriptive
4. Test your changes locally before submitting
5. **Open a pull request** against `main`, referencing the issue it addresses (e.g. `Closes #42`)

Please keep pull requests scoped to a single change. Large PRs that touch many unrelated things are harder to review, and we may request that you split up your PR.

## What's Welcome

- Bug fixes
- Questions
- New features or commands
- Documentation improvements
- Typo fixes
- Tests
- Style and best-practices improvements
- Anything else you think would improve the project! When in doubt, open an issue and ask

## Code Style

Try to match the style of the surrounding code. This project uses [pre-commit](https://pre-commit.com/).
